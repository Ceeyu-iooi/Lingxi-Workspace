# 灵犀设计规范

当前唯一设计依据为根目录 `design.md`。浅色与深色实例分别见 `/preview.html`、`/preview-dark.html`。修改业务界面时同步更新规范与预览。

六套主题在外观设置中选择，并应用到当前 Profile 的全部界面。视觉套件与主题套件固定采用横向陈列，底部圆点和透明侧边箭头导航，支持拖动及键盘，滚轮只滚动页面。窄屏保留左侧图标栏，页面缩放与字号设置分别处理；表格切换只更新数据，不改变行列位置。

主应用顶栏与侧栏共用主题填充色；独立 preview、计价与规范只继承浅／深模式，浅色导航白色、深色导航与正文一起使用默认雾蓝深色样式，正文及卡片保持中性表面。来源与模型明细的 JellyRadio 与容器顶部和右侧保持 18px 内边距；窄屏在标题下方靠右排列，保留同样的外侧留白。


共享状态由应用外壳管理：每次冷启动宽窗口直接展开侧栏，运行内切页、辅助窗口及托盘恢复保留状态。缩放只有一个写入口，设置、快捷键与重置共用，按Profile保存。主体四角10px，四周12px主题底色间隙。

规范目录支持原生滚动并隐藏滚动条。按钮、导航、页签与装饰文字不可选取，输入、正文及可复制数据保持正常选取；JellyRadio实心选中使用强调色与白字。浮层位置按实际渲染层几何换算，不能使用旧缩放变量补偏移。

帮助菜单的资源管理器采用CPU、内存、存储、网络四页大弹窗。可见指标页每秒采样，存储进入自动扫描并每秒读取进度、变化有界检查，网络限1000条/2MiB并脱敏；关闭释放。共享缓存与进程内存不相加。更新启动检查一次，日志区域280px内部滚动，下载显示真实百分比与已下载MB/总MB；下载关闭后继续，失败可重试，校验后确认安装。

窗口标题栏40px、圆角4px，标题空白可拖动；资源管理器960×640固定外框，供应商管理960×680，均受视口约束。存储分类共用颜色，点击在原窗显示明细；PID在最后一列。最近请求仅用量，来源明细选择立即反馈。

用量监测保持成熟排列与图表网格：累计、筛选、范围、账户、活动、趋势/模型与明细；筛选条填满一行，工作区和模型适当加宽，日期与模型面板跟随触发器实际宽度，不固定旧142px。侧栏全程固定Logo/头像/模块条纵坐标，宽度连续过渡。存储分类列表无横线；Profile身份和备份主动作采用明确字号、留白与表面层级。

## 工作区与供应商层级

用量监测保持成熟结构，不采用其他工作区的布局重构。总览将关键数量置于轻量统计带，项目与趋势作为辅助，待办队列作为主操作区；项目页左侧项目目录、右侧任务工作区，待办支持搜索与完成状态筛选；总结左侧历史月份，右侧长文本编辑和保存。热点采用来源栏、搜索和内容列表；记账复用用量日期、JellyRadio、图表及表格，趋势与分布各占一行，日期、分类、收支、金额和关键词共同控制当前分析与明细，默认时间最新在前。提示词与技能使用低对比筛选栏、独立工具条、主体资源卡与记录操作栏。

## 一致性的实现归属

设计依据仍只有 `design.md`。以下表格用于定位实现和验证责任，不复制另一套视觉数值。

| 能力 | 数据和状态归属 | 组件与样式归属 | 完成检查 |
| --- | --- | --- | --- |
| 主题、缩放 | Profile设置；共享主题预设与唯一缩放写入口 | 应用外壳及共享Token；页面只消费变量 | 浅深、125%缩放、保存／放弃、多窗口修订冲突 |
| 用量筛选 | 主应用和任务栏插件各自筛选；响应绑定已提交查询 | 现有日期／模型控件，禁止另做相似控件 | 模型或／其他条件且；快速切换、失败保留快照身份 |
| 小时趋势 | 服务端有效事件；`src/shared/usage-trend.ts`契约；日期和请求由`usage-trend-control.ts`持有 | 原JellyRadio、usageCharts；`usage-trend.css`只负责新增控件和缺口标记 | 24桶精确核对、未知／未来／缺口、日小时和曲线柱状、重试、隐藏释放 |
| 图表交互 | 数据宿主维护结果，usageCharts维护绘图和提示 | `frontend/compat/usage-charts.ts`；沿用图表令牌 | 鼠标／键盘提示、空数据、缩放、离页观察器与监听释放 |
| 技能资源 | 登记目录的只读索引；本地中文词目与Profile展示覆盖 | library-views、skillIdentity、ui-system及workspace-layout | 原名Tooltip、中文搜索、快速分页／失败快照、来源隔离、详情保存不改原文件 |
| 任务栏配置 | 主进程带修订号配置为权威；设置持有未保存草稿 | frontend/app/taskbar-settings.tsx与taskbar-settings.css；两入口共用严格类型组件及轻量样式预览 | 双窗口修改、保存失败和放弃、旧响应不覆盖新编辑 |

局部样式留在所属组件；共用数值进入现有Token，页面不得通过更高优先级重复覆盖实例。新增共享逻辑使用严格类型；保留的兼容DOM代码要通过实际入口操作验证。清理生命周期由创建该宿主的模块负责，外壳不提前释放仍留在页面中的实例；替换宿主内容前先释放其旧实例。

每轮只维护受影响操作链：先确定数据／状态／组件责任，完成共享实现及调用方，再检查加载、失败、窄屏、缩放与相关多窗口状态，最后更新规范、浅深预览和覆盖清单。发现旧规则冲突时替换旧条目。尚未迁移的兼容控制器和历史CSS作为明确技术债保留，不宣称一次局部修改完成全项目迁移。

设置采用中性浅灰导航、章节标题与白色设置分组，主标题、设置名称、描述和操作有不同字重与间距。API供应商采用品牌身份与Key数量、Key行列表和底部48px虚线添加入口；新增原区展开紧凑双列表单，查询地址占满一行，名称/Key并排，窄屏单列，错误保留输入。预设供应商品牌标识从官方网站/官方仓库取得，来源、许可和摘要位于static/assets/providers；自定义供应商不冒用品牌。

侧栏展开时品牌背景覆盖标识及完整字标，收起时限制在64px轨道内；导航字重500。Codex来源使用单个黑色官方标识，浅色不反白，深色反白；中性选中背景下始终可见。应用和弹窗标题栏40px，窗口圆角仍为4px。更新清理等待首页及检查更新均就绪，已使用的包删除，更新的新包保留。

独立`preview.html`和`preview-dark.html`分别以浅色／深色开始，读取配置和主题切换为本窗口预览，不写Profile或广播覆盖主窗口草稿；嵌入工作台的预览仍沿原显式保存入口。
