# TypeScript 架构迁移方案与实施边界

目标为 React + TypeScript + Vite SPA、Node.js + TypeScript + SQLite。保留所有有效页面与业务功能，只应用本轮明确指定的界面、Profile 与更新变化。源码版本为0.0.32，实施状态与验收状态分开记录。

## 功能映射

| 原职责 | 新位置 | 保持的契约 |
|---|---|---|
| HTTP、启动与生命周期 | src/server/main.ts、scripts/web_launcher.mjs | API 路径、返回值、实例身份、正常退出与迁移重启 |
| 项目、待办、记账、总结、通知 | business.ts、parsers.ts | 编辑、完成、筛选、导入精度与去重 |
| 提示词、模板、技能、热点 | prompts.ts、market.ts、skills.ts、news.ts | 版本冲突、原始草稿、只读扫描、来源和数据边界 |
| 用量与供应商 | monitor.ts、codex.ts、agents.ts、usage-accounts.ts、provider-*.ts | 未知≠零、最小证据、归属、去重、Key隔离及真实账单 |
| 历史计价 | pricing.ts、usage-summary.ts | 历史价格与汇率、Decimal、分项、双币种、准备完成才开启 |
| Profile、备份与维护 | profile.ts、backups.ts、maintenance.ts | 单实例身份、独占写入、口令加密、事务恢复与停写迁移 |
| 前端页面与交互 | frontend/app、frontend/compat | React壳和路由，既有编辑器/图表/保存/焦点通过适配保留 |
| 桌面与安装 | desktop、scripts/stage_backend.cjs | 独立随机端口、安全原生桥、程序旁资料、安装与便携双包 |

## 执行顺序

1. 从旧实现捕获合成业务与用量基准，独立记录 API、金额、日期和证据契约。
2. 建立共享接口与 Node 服务，逐模块对照业务、提示词、日志、供应商与历史计价；保留旧实现直到正式切换。
3. React接管应用壳、路由与页面入口，通过compat保留现有交互；新入口与后端严格类型检查，compat尚未全面严格类型化，不把文件后缀当作类型安全证明。
4. 替换桌面后台，验证版本、PID、Profile与service身份，完善程序旁便携资料、更新缓存和加密备份。
5. 在独立公开导出目录安装、构建与启动，复查样式、交互、浅深色、窄屏、字号/缩放、失败保留与性能。网页与真实原生验收分别记录。
6. 正式8765验收后构建并核验双包；通常要求真实Setup、桌面和便携、安装/升级/卸载全部通过后提升与发布。本次v0.0.32由用户明确取消EXE验收，回执与发布说明记录取消，不能标为通过。
7. 新程序可用后执行本轮已授权的本机旧Profile一次性清空，保留源码与外部Agent日志，最终回到无Profile首次启动；通用升级不清空用户资料。
8. 更新文档、提交与两个仓库同步，远程源码独立构建复验；Release标题与标签仅v版本号，中文参考格式并提供双包。

## 验证原则

旧版对照负责数值和契约；合成日志负责继承、路径变动、去重与未知值；网页操作和截图负责页面交互；真实窗口与安装流程负责原生行为。构建成功、注入接口检查、源码核验均不能代替实际三端验收。验证记录保留在项目外隔离环境和私有deliverables，不进入公开源码。
