# 每日小时用量视图

0.1.25已实现本机Codex、ZCode、DSH的单日Token小时视图，主应用和任务栏插件共用控件及图表。供应商小时视图仍待逐个验证，当前保留日视图。

## 数据边界

有效消费的`at`表示来源记录时间，不等同于推理开始时间。不按耗时拆分Token，不把一笔请求摊入多个小时，不从日汇总、余额或额度反推。沿用来源请求身份、fork与旧Codex记录排除规则，不新建采集器、不改写原始证据。

小时模式提供按日／按小时、范围内单日、前一天／后一天及日期输入，复用曲线／柱状。小时只展示Token；费用保留日视图。模型、服务商、工作区和连接继续使用现有筛选，模型按或、其余按且。大范围中选择一天，不能把多天同一时刻偷偷相加。

## 接口与状态

`/api/usage/chart?scope=codex&granularity=hour&date=YYYY-MM-DD&timezone=Asia/Shanghai&metric=tokens`

后端校验来源、日期、时区和模型筛选，将上海单日转换为UTC半开区间`[start,end)`。从索引限定的完整有效事件集流式读取热字段，不使用最近100条限制。`summaryAccumulator`同时生成24桶、模型计数和同条件摘要，BigInt精确累加，缓存与推理保留子集口径。

契约位于`src/shared/usage-trend.ts`，包含24桶、UTC小时起点、来源覆盖、未知分项与数据版本。超过安全整数以十进制字符串传递；图形使用近似几何，提示保留精确值。求和核对使用`knownTotal`并同时核对请求数和未知字段，不能把null当零宣称完整。

| 状态 | 含义 | 呈现 |
| --- | --- | --- |
| known / zero | 已登记日志采集就绪且证据完整；零仅限该范围 | 正常量／零 |
| partial | 已有记录，采集或覆盖尚未核验完整 | 已知量及部分状态 |
| unknown | 至少一笔总量未返回 | 断点、未知提示和已知部分 |
| unobserved | 无记录且覆盖尚未核验 | 缺口，不能补零 |
| future | 尚未来到且无真实记录 | 留空及未来提示 |

每桶`total`为可展示量，未知、缺口和未来为null；`knownTotal`保留已知部分。未来时间出现真实记录时保留事实、标记部分，不删除以迎合时钟。

## 性能与交互

压缩数据库的查询计划命中现有`compact_events_scope`，不新增索引或派生表。仅保留24个汇总器和模型计数，不解码对话／证据正文。缓存复用既有8MiB预算，按Profile、筛选、事件版本、采集覆盖和分钟隔离；事件修改按既有版本统一失效。

严格类型的`usage-trend-control.ts`拥有模式、日期、请求取消、最新结果、错误重试和整点更新。HTTP可取消；原生桥返回另做最新查询校验。刷新保留上次真实结果和原查询身份，失败标记并允许重试。隐藏停止查询及计时，详情关闭过渡结束释放图表监听；恢复再核验。显式刷新及采集覆盖变化不能只依赖Token版本变化。

## 核验与后续

隔离合成资料覆盖上海午夜、23:59、跨UTC日期、超过100条、模型或／其他条件且、超大整数、未知字段、未来和覆盖缺口、压缩结构、缓存失效及响应竞争。小时视图沿用已入账事件，来源采集与fork正确性继续依照`TOKEN_ACCOUNTING.md`独立核验。页面验证覆盖主应用与插件、曲线／柱状和浅深／窄屏，不把隔离验证当作真实Windows任务栏验收。

供应商下一阶段先核验逐次时间字段、时间语义、分页完整性、Key范围及时区，再开放小时能力。不能还原未曾采集的历史。
