# Figma 与前端协作

设计文件：[灵犀工作坊 · 前端设计与代码映射](https://www.figma.com/design/wI0bSEDbcHfyrLJvvoEsfR)。

项目映射在 `design/figma-map.json`；完整创建记录和待完成项目在 `design/figma-state.json`。画板使用演示数据，应用的数据与业务逻辑仍由现有前后端负责。

## 在 Figma 修改后同步前端

1. 在“01 · 工作台页面”选择目标画板或区域，调整布局、间距、颜色或文字层级。
2. 复制该画板或区域的链接，在这个项目告诉 Codex：

   > 按这个 Figma 画板的最新改动同步前端：粘贴链接。复用现有组件，保留业务功能。

3. Codex 依据映射找到页面和共享样式，通过已连接的 Figma 插件创建本次文件会话，读取目标节点的最新 `get_design_context` 与截图；必要时读取其子区域及变量。读取成功后再修改相应源码。
4. 实施采用现有 React、TypeScript、DOM 控制器与 CSS 的职责，不把参考代码整页覆盖到项目，也不把演示金额、待办或图表值写成正式固定数据。
5. 在受影响入口验证布局、操作、主题与响应式行为，更新 `design.md`、共享浅深预览及映射基线。构建与发布遵循当前任务授权和项目规则。

同步由用户发起。Figma 的实时拖动不会直接修改运行中的应用；本项目没有后台监听器或自动覆写服务。Figma 的交互原型也不等于业务代码。

## 改动范围与冲突

- 有节点链接时以该节点为范围；只有文件链接时先读取页面清单并定位目标，不猜测节点 ID。
- 页面节点对应具体模块；共享顶栏、侧栏、组件或变量的变化可能影响多个模块，实施前沿现有引用确认影响范围。
- Figma 是本次用户指定的视觉输入，实施后将结果写回本地规范；接口、权限、状态、查询口径及业务保存边界沿用原权威实现。
- 先比较本地源码指纹和上一次设计基线。双方都变更时核对冲突，保留用户修改；不重建整份文件，不盲目以旧的本地快照覆盖 Figma。
- Figma 返回的参考代码需要按项目适配。只有实际高保真读取成功，才能开始据其修改；截图仅作视觉对照。

## 当前能力和限制

- `design/figma-map.json` 的 `status` 区分已创建、待创建及待验证画板；只有实际返回的节点 ID 才写入映射。
- Figma 使用已提供的 Noto Sans SC；正式应用使用 Segoe UI、Microsoft YaHei UI 和系统字体，字形存在差异。
- 当前 Ceeyu 是 Starter / View 席位，变量集合只允许一个模式，因此采用 Light、Dark 两套集合。插件调用还受账户额度限制；额度不足时停止读写并保留完成记录，不将未执行项目记为通过。
- 本轮已遇到 Starter MCP 调用额度耗尽。尚未完成全部画板、主题实例、共享组件整理和从设计读取到代码的完整验证，具体剩余项见状态记录。

## 再次从代码整理到 Figma

仅在用户明确要求“把代码更新到 Figma”时执行这个方向，防止覆盖用户的设计改动。

1. 用独立 Profile 运行当前构建，填入明确标识的演示数据；监测、真实凭据目录、真实账单和个人资料与该环境隔离。
2. 通过浏览器工具读取可见 DOM 与样式。闭合菜单、隐藏元素、屏幕外内容不作为当前画板图层；返回压缩 JSON，避免嵌套或字符上限截断。
3. 本地将原有 SVG 解析到对应素材槽位，使用 `scripts/figma/pack-scene.cjs` 压缩结构。文件不能包含 Profile 数据或凭据。
4. `scripts/figma/scene-builder.js` 由 Figma 插件的 `use_figma` 执行；它不是网页运行脚本，也不会自行登录 Figma。每次传入真实返回的文件、页面和父节点 ID。代码参数不得超过插件的 50,000 字符上限。
5. 场景文件在 `design/figma-scenes`，供本次受限导入恢复使用。后续前端变化后应重新读取实际界面，不能将这些快照当成永不更新的设计来源。
6. 核对可编辑文字、矢量、布局、素材和截图；只清理本轮拥有且已记录 ID 的临时参考。收尾清理隔离 Profile、临时捕获脚本与构建环境。

无需向工作台添加 Figma API Key。设计的读写由 Codex 当前连接的 Figma 插件完成。
